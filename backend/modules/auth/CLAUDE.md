# CLAUDE.md — modules/auth

Rules for AI coding agents working in `backend/modules/auth/`. Project rules: [../../../CLAUDE.md](../../../CLAUDE.md).

## Sources of truth

- Session flow, user ID and access: [docs/backend/AUTH.md](../../../docs/backend/AUTH.md).
- `users` table: [docs/backend/SCHEMAS.md](../../../docs/backend/SCHEMAS.md#users-modulesauth).

## Module boundary

- `service.py` is the public interface of the module. Other modules import only `service.py` and `schemas/`, never `models/` or `database.py`.
- Service functions take the session of the request as the first argument, never commit and never open their own session: [docs/backend/DESIGN.md](../../../docs/backend/DESIGN.md#database-connection). They return Pydantic schemas, never ORM objects.
- The module has no routers. Endpoints are provided by `modules/main`: [docs/backend/API.md](../../../docs/backend/API.md).

## Database

- Tables are declared on `AuthBase` only. No foreign keys to tables of other modules.
- `users.id` is generated by PostgreSQL (`gen_random_uuid()`). Code never generates or accepts a client `id`.
- Migrations: one chain for the whole Backend in `backend/migrations`: see [SCHEMAS.md](../../../docs/backend/SCHEMAS.md#migrations). A model change ships with a migration in `backend/migrations/versions/`, and `alembic check` reports no new operations.

## Tests

- `tests/` runs against PostgreSQL from `TEST_DATABASE_URL`. Fixtures: `backend/conftest.py`.
