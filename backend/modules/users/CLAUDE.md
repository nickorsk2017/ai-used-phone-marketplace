# CLAUDE.md — modules/users

Rules for AI coding agents working in `backend/modules/users/`. Project rules: [../../../CLAUDE.md](../../../CLAUDE.md).

## Sources of truth

- Module responsibility and allowed calls: [docs/backend/DESIGN.md](../../../docs/backend/DESIGN.md#modules), [docs/backend/AUTH.md](../../../docs/backend/AUTH.md#modules).
- `users` table: [docs/backend/SCHEMAS.md](../../../docs/backend/SCHEMAS.md#users-modulesusers). User ID: [docs/backend/AUTH.md](../../../docs/backend/AUTH.md#user-id).

## Module boundary

- `services/` is the public interface of the module, called by `modules/main` and `modules/auth`. `services/__init__.py` re-exports the public functions: `services/crud.py` has the database functions (take the session). Other modules import only `services` and `schemas/`, never `models/` or `database.py`.
- The module knows nothing about sessions, tokens or cookies: they belong to `modules/auth` and `modules/main`.
- Service functions take the session of the request as the first argument, never commit and never open their own session: [docs/backend/DESIGN.md](../../../docs/backend/DESIGN.md#database-connection). They return Pydantic schemas, never ORM objects.
- The module has no routers. Endpoints are provided by `modules/main`: [docs/backend/API.md](../../../docs/backend/API.md).

## Database

- Tables are declared on `UsersBase` only. No foreign keys to tables of other modules.
- `users.id` is generated by PostgreSQL (`gen_random_uuid()`). Code never generates or accepts a client `id`.
- Migrations: one chain for the whole Backend in `backend/migrations`: see [SCHEMAS.md](../../../docs/backend/SCHEMAS.md#migrations). A model change ships with a migration in `backend/migrations/versions/`, and `alembic check` reports no new operations.

## Tests

- `tests/` runs against PostgreSQL from `TEST_DATABASE_*`. Fixtures: `backend/conftest.py`.
