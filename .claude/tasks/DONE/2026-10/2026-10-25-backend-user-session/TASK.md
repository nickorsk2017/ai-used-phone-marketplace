# TASK — 2026-10-25-backend-user-session
owner: Engineer
immutable: true

## Requirements
- R1: `modules/auth`: `users` table per docs/backend/SCHEMAS.md#users-modulesauth. `id` generated by PostgreSQL (docs/backend/AUTH.md#user-id). Own Alembic migrations and own version table (SCHEMAS.md#migrations).
- R2: `POST /api/users` (Public) per docs/backend/API.md: creates a user from `{whatsapp, first_name, last_name}`, returns the user with the generated `id`. The client cannot set `id`.
- R3: `GET /api/users/{id}` (Owner) per API.md and AUTH.md#access: `X-User-Id` must match `{id}`. An unknown user returns 404, so the Frontend resets the session (AUTH.md#session-flow step 5).
- R4: `modules/main`: FastAPI app with the `/api` prefix, resolves `X-User-Id`, calls `modules/auth` only through its public interface (docs/backend/DESIGN.md#modules). Entry point `backend/main.py` (docs/backend/STRUCTURE.md). The Frontend dev server can call the Backend from another origin.
- R5: UI unlock: with the Backend running, the My listings page creates the user, stores `user_id` in `localStorage` and shows "Add new phone" with an empty list. After a reload the session is restored.
- R6: Makefile targets to install, run, test and migrate the Backend (docs/INFRA.md#makefile-targets).

## Acceptance
- A1: `pytest` for `modules/auth` and `modules/main` passes against PostgreSQL. `ruff check` passes.
- A2: Tests: create user (201, UUID from the database, `id` in the body rejected), invalid body (422), own user (200), missing `X-User-Id`, foreign `X-User-Id`, unknown `id`, malformed `id` (404).
- A3: `alembic upgrade head` and `downgrade base` work on an empty database. Version table is owned by `auth`.
- A4: Frontend `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` pass.
- A5: Browser check against the running Backend: R5, and a deleted user in the database brings back the user creation modal.

## Constraints
- Scope: user creation, user loading, UI unlock. Out of scope: `PUT /api/users/{id}`, `modules/phones`, `modules/rag`, rate limit.
- `GET /api/my-listings` is not implemented in this task: the Frontend returns an empty list while `NEXT_PUBLIC_API_STUB=true`.
- Request and response bodies follow frontend/schemas/userSchemas.ts and frontend/types/user.d.ts (discrepancy D1 of 2026-10-25-frontend-my-listings-page).
