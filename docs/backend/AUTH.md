# AUTH.md

v1.0 uses a browser session without registration. The user is identified by `user_id` stored in the browser `localStorage`. Why: see [Tradeoffs](#no-registration-in-v10).

## Session Flow

A user is needed only to create and manage listings. Search, Phone details and the "Deal" button work without a user, so a buyer never sees a form.

1. When the user opens the My listings page, the Frontend reads `user_id` from `localStorage`.
2. If `user_id` is missing, the Frontend shows a modal window for creating a user with the required fields. Fields: see [SCHEMAS.md](SCHEMAS.md#users-modulesauth).
3. The Frontend calls `POST /api/users`. The Backend creates the user and returns `id`. The Frontend saves it to `localStorage` as `user_id`.
4. If `user_id` exists, the Frontend calls `GET /api/users/{id}` to load the user data.
5. If the Backend returns 404, the Frontend removes `user_id` from `localStorage` and shows the modal window from step 2.

## User ID

- `user_id` is a hash value.
- In PostgreSQL it is stored in the `id` field of the `users` table (primary key).
- The `id` is generated by PostgreSQL on insert: column default `gen_random_uuid()` (UUID v4). The Backend and the Frontend do not generate it, and the client cannot choose its own `id`.

## Access

- The Frontend sends `user_id` in the `X-User-Id` header with every request.
- `modules/main` resolves the header to a user. Access levels `User` and `Owner` in [API.md](API.md) are checked against this user.
- `user_id` works as a bearer token: whoever has it acts as the user.
- Public endpoints never return `user_id`. The contact of a listing owner is returned by `GET /api/phones/{id}/contact` by the listing ID.

## Tradeoffs

### No registration in v1.0

v1.0 has no authorization and no registration, as required by [TASK.md](../TASK.md#out-of-scope-for-v10). The PoC is used to collect feedback, so a user only needs to try the product once or twice. Long sessions are not needed.

### Limitations

- This authorization is simplified on purpose, according to [TASK.md](../TASK.md#out-of-scope-for-v10).
- A session is tied to one browser. Clearing `localStorage` or using another device creates a new user. The previous listings stay with the old `id` and are not accessible.
- There is no logout and no session expiration.

Full authorization and registration: see [ROADMAP.md](../ROADMAP.md#production-baseline).
