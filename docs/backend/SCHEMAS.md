# Backend Schemas

Data models of all Backend modules. Module responsibilities: [DESIGN.md](DESIGN.md#modules).

## users (`modules/users`)

| Field | Type | Description |
| --- | --- | --- |
| `id` | UUID, PK | User ID, generated by PostgreSQL (`gen_random_uuid()`). Signed in the session token: see [AUTH.md](AUTH.md#session-token) |
| `whatsapp` | string | WhatsApp number, shown separately from the listing text |
| `first_name` | string | First name |
| `last_name` | string | Last name |
| `created_at` | timestamp | Creation date |

## phones (`modules/phones`)

| Field | Type | Description |
| --- | --- | --- |
| `id` | UUID, PK | Listing ID, generated by PostgreSQL (`gen_random_uuid()`) |
| `user_id` | UUID | Owner, `users.id` |
| `model_code` | string | Model code of the US version from the LLM, for example `A2483`. Format: 2 to 32 characters, uppercase Latin letters, digits and `-` (`^[A-Z0-9-]{2,32}$`, the value is converted to uppercase before the check), checked on `POST /api/phones/description` and `POST /api/phones` |
| `model_name` | string | Model name, for example `iPhone 13 Pro` |
| `os` | enum | `ios`, `android` |
| `camera_megapixels` | integer | Main camera resolution. From the LLM, can be edited by the user |
| `battery_capacity` | integer | Battery capacity, mAh. From the LLM, can be edited by the user |
| `display_size` | decimal | Display size, inches. From the LLM, can be edited by the user |
| `description` | text | Model description generated by the LLM, can be edited by the user |
| `condition` | enum | `like_new`, `average`, `for_repair` |
| `condition_note` | text | The user's note about the phone condition |
| `price` | integer | Price, positive. In v1.0 the currency is USD |
| `created_at` | timestamp | Creation date |
| `updated_at` | timestamp | Update date |

## search_index (`modules/rag`)

`search_index` (`modules/rag`) is a read model for search. It stores copies of the listing fields used by the search, so the module queries only its own table.

| Field | Type | Description |
| --- | --- | --- |
| `phone_id` | UUID, PK | Listing ID, `phones.id` |
| `embedding` | vector(1536) | Embedding of model name, description and condition note (OpenAI `text-embedding-3-small`) |
| `model_code` | string | Copy of `phones.model_code` |
| `model_name` | string | Copy of `phones.model_name` |
| `os` | enum | Copy of `phones.os` |
| `camera_megapixels` | integer | Copy of `phones.camera_megapixels` |
| `battery_capacity` | integer | Copy of `phones.battery_capacity` |
| `display_size` | decimal | Copy of `phones.display_size` |
| `description` | text | Copy of `phones.description` |
| `condition_note` | text | Copy of `phones.condition_note` |
| `condition` | enum | Copy of `phones.condition` |
| `price` | integer | Copy of `phones.price` |
| `updated_at` | timestamp | Update date |

- HNSW index on `embedding` with cosine distance.
- The copied text and specification fields are the reranker input: see [RERANKING.md](../ai/RERANKING.md#input).

## Migrations

The Backend has one Alembic migration chain for all modules: `backend/alembic.ini` and `backend/migrations/`. Reason and limitations: see [Tradeoffs](#tradeoffs).

- Version table: `alembic_version`.
- `backend/migrations/env.py` collects the metadata of every module with tables (`UsersBase.metadata`, `PhonesBase.metadata`, `RagBase.metadata`). A new module adds its Base there.
- `0002_create_phones_and_search_index.py` creates the `vector` extension (`CREATE EXTENSION IF NOT EXISTS vector`), `phones` and `search_index`. The downgrade drops the tables and keeps the extension.
- Revisions are numbered: `0001_create_users.py`, `0002_<slug>.py`.
- Commands: `make migrate` (up to head, also run by `make up-all`), `make migration MSG="<description>"` (autogenerate the next revision).
- No foreign keys between tables of different modules. Modules reference each other by ID (`phones.user_id`).

## Tradeoffs

- One migration chain instead of a chain per module. Chosen for the PoC: one `alembic.ini`, one version table, one `make migrate`. Limitation: a module cannot be moved to a separate database together with its own migration history. Rejected: a chain per module with the version table `alembic_version_<module>`. It is restored when a module is moved to a separate service: see [DESIGN.md](../../BRIEF.md#backend).
